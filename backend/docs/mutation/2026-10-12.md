### EXPECTED class justification and the mutmut 2.5.1 config-skill question

Three EXPECTED classes, justified per class above: annotation forward-refs
(kill instrument: mypy, which already scopes this module), `@wraps` decorator
removal (metadata only), and the `CapabilityPermission.message` None mutation
(observationally equivalent via DRF's default_detail substitution).

Config-skip facts, verified against the installed mutmut 2.5.1 package this
session (not assumed): there is no `mutmut.conf` mechanism and no per-line or
per-mutant skip directive. What exists: CLI flags `--disable-mutation-types`
/ `--enable-mutation-types` (type codes: operator, keyword, number, name,
string, fstring, argument, or_test, and_test, lambdef, expr_stmt, decorator,
annassign), which the config-file merge also accepts as `[tool.mutmut]` keys
of the same name; `paths_to_exclude` (path regexes); `pre_mutation` /
`post_mutation` shell hooks; and a `mutmut_config` hook module (mutmut's
optional user hook, absent from this tree) whose
`SkipException` marks individual mutants `skipped` (reported separately from
killed/survived, so the score stays honest). None of these is recommended for
the EXPECTED cohort: skipping the `decorator` type would silence exactly the
two survivors at hand but is a harness choice the orchestrator/RE should make
deliberately, and skipping `string` would also hide the REAL[hole] string
vocabulary below — the very mutants this triage exists to surface.
